# 科技塔罗牌首页视觉系统优化设计

日期：2026-04-23  
范围：仅首页，不包含牌库、抽牌结果页、后台

## 1. 目标

将当前首页从“已经有风格的功能页”提升为“品牌气质成立、同时具备产品引导能力的首页”。

这次优化只解决首页的三个问题：

1. 首屏需要先建立科技塔罗牌的世界观，但不能像纯海报。
2. 首页需要自然引导用户进入“抽三张牌”，但不能为了转化牺牲气质。
3. 导航、状态条、Hero、后续区块之间要形成统一的视觉语言，而不是各自成立。

本轮不改动信息架构，不新增新页面，不扩展功能范围。重点是视觉系统、节奏和首屏体验。

## 2. 设计定位

首页定位为“有仪式氛围的产品首页”。

用户进入页面后的感受应是：

- 第一眼：这是一个完整的、独特的赛博占卜品牌
- 第二眼：这不是概念图，而是一个真的可以使用的网站产品
- 第三眼：最自然的下一步是开始抽牌

设计关键词：

- 炼金复古
- 赛博神谕
- 克制的戏剧性
- 产品化
- 细密而非喧闹

## 3. 用户与成功标准

首页主要面对第一次进入网站的人。他们可能是被“科技塔罗牌”这个概念吸引，也可能是直接来体验抽牌。

首页成功的标准：

- 用户能在 3 秒内理解网站主题
- 用户能在 5 秒内知道首页主操作是“开始抽三张”
- 用户会觉得网站有明显气质，而不是普通工具页
- 首屏下沿能明确暗示下面还有内容，用户知道可以继续浏览

## 4. 核心方向决策

已确认的方向：

- 整体气质：平衡型，不走纯神秘海报，也不走纯工具后台感
- 首屏目标：品牌成立，同时自然引导去抽牌
- 右侧结构：主视觉图 + 一张悬浮卡牌
- 推荐方案：平衡推荐版

因此本轮首页不采用以下方向：

- 不做满屏主视觉占据一切的“展览海报版”
- 不做首屏直接堆大量产品模块的“效率工具版”
- 不做过多神秘符号、法阵、星轨抢视线的“重玄学特效版”

## 5. 设计系统

### 5.1 色彩

颜色分为三层：

- 主底色：深曜石蓝黑，用于 Hero 主背景、深色按钮、深色容器
- 主文本与金属线框：羊皮纸金，用于标题、描边、金属装饰、强调信息
- 少量冷色点缀：冷铜青，用于星轨、能量感、局部对比

规则：

- 冷色只作为点缀，不成为主色
- 金色不做大面积实体填充，主要用于线、字、边框、微光
- 页面不能出现新的跳脱色相，避免视觉系统失焦

### 5.2 字体

- 标题继续使用现有的宋体/衬线方向，强调“神谕感”
- 正文与交互文本使用现代中文无衬线，保证可读性和产品感
- 英文辅助字保持小尺寸、高字距、低存在感，只服务气质，不承担主信息

### 5.3 间距

- 基础间距单位：8px
- 首屏内部采用更大步长，关键区块之间优先用留白建立节奏，而不是用边框堆层级
- 文案块内部保持更稳定的垂直节奏，避免 Hero 左侧因为文字和按钮堆叠显得发闷

### 5.4 圆角

- 导航、筛选、一般按钮保持克制的小圆角
- Hero 主视觉容器和悬浮卡牌使用更大的圆角，形成首页的视觉重心
- 大圆角只留给真正的主角，不扩散到全页面所有模块

### 5.5 阴影

- Level 1：导航和轻交互，仅保留非常淡的浮起感
- Level 2：Hero 主视觉容器，中等深度阴影
- Level 3：悬浮卡牌，最重阴影，用来做首页中最明确的前后层次

### 5.6 动效

- 法阵与星轨继续保留，但透明度和存在感降低
- Hero 右侧悬浮卡牌做极轻微漂浮或呼吸感，成为首屏真正的动态焦点
- 按钮 hover/focus 使用利落的产品式反馈，不做夸张位移
- 导航吸顶保留，但应更精致，不像默认组件条

动效原则：

- 不抢内容
- 不制造噪音
- 让页面“活着”，但不让页面“表演”

## 6. 首页结构调整

### 6.1 顶部导航

目标：更轻、更准，不与 Hero 争主角。

调整方向：

- 降低导航本身的块感
- 保留品牌、锚点、后台入口、随机看一张
- 强化精致度，包括边线、背景透明度、文本节奏
- 导航作为产品框架存在，而不是视觉主角

### 6.2 Hero 左侧

目标：用尽量少的信息，建立品牌与行动指向。

保留结构：

- eyebrow
- 大标题
- 一段核心说明文案
- 主次 CTA
- 一条极简产品能力摘要

层级规则：

- 标题是绝对主角
- 正文负责建立世界观与幽默定位
- `开始抽三张` 是主要动作
- `浏览牌库` 是平衡动作
- 能力摘要只做轻提示，不应比正文更抢眼

### 6.3 Hero 右侧

目标：让首屏同时拥有品牌画面和“卡牌产品”的证据。

结构：

- 一张主视觉图作为背景载体
- 一张悬浮卡牌叠在主视觉图边缘

规则：

- 主视觉图负责世界观和氛围
- 悬浮卡牌负责把抽象概念变成可感知的产品对象
- 悬浮卡牌不能太小，否则会失去存在感
- 悬浮卡牌不能遮掉主视觉最重要的画面区域

### 6.4 首屏下沿与状态条

目标：让首页像网站，而不是停在一张封面图上。

调整方向：

- 首屏下沿刻意露出下一段内容
- 状态条从“纯统计横条”升级为“产品能力摘要条”
- 数字、标签、边框和背景关系要更精致，避免像后台 dashboard

## 7. 内容策略

首页内容策略是“少而成立”。

具体要求：

- 不新增解释性大段文案
- 不塞入多余模块证明自己“内容丰富”
- 不添加假数据、假口碑、假用户案例
- 保留幽默感，但首页文案整体更像品牌文案，不是段子合集

首页的幽默应体现在：

- 产品设定本身
- 核心说明句的反差感
- 局部标签和命名

而不是把所有文案都写成梗。

## 8. 实施范围

本轮允许修改：

- `app/globals.css`
- `components/TechTarotApp.tsx`
- 首页所需的轻量结构与文案层级

本轮不修改：

- API
- 数据模型
- 抽牌逻辑
- 后台功能
- 牌库和详情页的主体结构

## 9. 验收标准

实现完成后，应满足以下标准：

- 首屏在桌面端第一眼具备明确品牌感
- 主按钮在不破坏气质的前提下足够明确
- 首屏右侧“主视觉图 + 悬浮卡牌”层级清晰
- 导航、Hero、状态条之间的风格连续
- 页面仍保留炼金复古科技气质，但不显得繁杂
- 首屏向下有自然延续感，用户知道后面还有内容
- 移动端不会因为大标题、卡牌悬浮或按钮布局产生拥挤和溢出
- 不新增控制台报错，不引入与现有视觉系统冲突的新颜色

## 10. 实现顺序

推荐按以下顺序实现：

1. 先重整首页设计令牌和主背景层次
2. 调整导航气质与吸顶样式
3. 重做 Hero 比例、左右结构和 CTA 层级
4. 重设右侧主视觉容器与悬浮卡牌位置
5. 优化状态条与首屏下沿衔接
6. 最后统一微交互、响应式和节奏细节

## 11. 风险与边界

主要风险：

- 如果特效层太重，首页会重新变成“概念海报”
- 如果产品元素过强，首页会失去神秘感
- 如果状态条太像统计卡片，会破坏首页的品牌感

规避方式：

- 所有装饰元素都服务于主结构，不单独争夺焦点
- CTA 明确，但不做过亮、过厚、过大
- 让悬浮卡牌成为产品感的承担者，而不是新增更多功能块
